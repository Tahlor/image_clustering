Five-minute technical primer

Chatbots and RAG

A chatbot is the conversation interface. RAG supplies current, authoritative evidence. Tools supply live or private facts. Deterministic code handles rules and calculations. The LLM interprets the request, coordinates the pieces, and explains the result.

What RAG means

  1. A user asks a question.
  2. The system searches an approved knowledge base.
  3. It filters and reranks the best passages.
  4. The passages and question are supplied to the LLM.
  5. The LLM synthesizes a grounded answer, ideally with citations.

Vocabulary

chunkingembeddingssparse searchdense searchhybrid retrievalrerankermetadata filtergrounding

  • Sparse/keyword search: exact codes, drug names, policy numbers, quoted language.
  • Dense/vector search: paraphrases and semantic similarity.
  • Hybrid search: combines both; a reranker then scores candidates more carefully.
  • Metadata: plan, product, state, effective date, document type, and access rights.

RAG versus fine-tuning

RAG changes what information the model can use at inference time. Fine-tuning changes the model's repeated behavior.
  • Use RAG for private, changing, authoritative, and citable knowledge.
  • Use fine-tuning for output format, repeated behavior, task adaptation, style, or a smaller specialized model.
  • Fine-tuning is not a sensible database-update strategy for changing benefit policies.

Chatbot versus agent

A chatbot is the surface. An agent lets a model choose and sequence tools over several steps. Prefer deterministic workflows when the steps are known; add model-directed planning only where it creates measurable value.

Evaluation

How RAG fails—and what to measure

Retrieval failure

The right source is absent, buried, badly chunked, or outranked.

Wrong authority

Right topic, wrong plan, state, product, member, version, or effective date.

Synthesis failure

Correct evidence is present but misread, exceptions are lost, or the answer extrapolates.

Security failure

The model or retrieval layer exposes information the user is not authorized to access.

Evaluate three layers

  • Retrieval: evidence recall, authority/version, filters, reranker quality.
  • Answer: correctness, citation support, completeness, contradiction, abstention.
  • Workflow: resolution, repeat contact, corrections, complaints, appeals, latency, cost, privacy, and subgroup burden.
Pretend you started the job

Four hypothetical initiatives

1. Payment-integrity reviewer workbench

Rank claims or episodes by expected validated value and reviewer effort; retrieve governing evidence; parse attachments; create a cited evidence packet. Optimize precision and value at real queue capacity, not anomaly score alone.

Measures: validated dollars per hour, precision at capacity, reviewer time, overturns, false-positive/provider burden.

2. Prior-authorization intake and evidence copilot

Classify pages, link attachments, validate plan/effective date, retrieve the correct policy, map evidence to criteria, identify missing information, and create a structured cited summary for human review.

Boundary: improve completeness and review readiness before considering autonomous judgment.

3. Member benefits-and-claims answer assurance

Use RAG for policy, tools for live facts, deterministic calculations, citations, verification, abstention, and warm transfer. Start with a narrow set of high-volume intents rather than a universal chatbot.

Measures: exact correctness, source support, resolution, repeat contact, complaints, language/accessibility, privacy.

4. Enterprise evaluation and confidence platform

Version datasets, models, prompts, tools, retrieval corpora, rubrics, thresholds, and adjudication. Support risk–coverage curves, random audits, launch evidence, production replay, and vendor-change regression.

Guardrail: build reusable components from real use cases, not an abstract platform without users.

My lane is not autonomous healthcare judgment. It is turning messy multimodal evidence and probabilistic models into a cited, calibrated, reviewable workflow that helps the accountable person make a better decision.

It is not a Vantage2 route, a generic image viewer, the static HTML bundle, or an extraction review surface. Start with [`../REVIEW_TOOL.md`](../REVIEW_TOOL.md), then use [`REVIEW_WORKFLOW.md`](REVIEW_WORKFLOW.md) for detailed operation.

## Workflow status

| Workflow or subsystem | Status | Canonical entry point | Notes |
| --- | --- | --- | --- |
| Conservative clustering library | **Active** | `image-cluster`, `image_clustering.clustering` | The primary identity decision is same physical document scene, not form-template similarity. |
| Unique crop recovery | **Active baseline** | `image-crop`, `image_clustering.cropping` | Downstream of clustering; audit crop-required and partial outputs before unattended production use. |
| Full evaluation/reporting | **Active** | `scripts/evaluate_dataset.py` | Produces inventory, clustering/crop reports, static HTML review, validation, and final report. |
| Physical-document duplicate/occlusion review | **Active; preferred for human review** | [`../REVIEW_TOOL.md`](../REVIEW_TOOL.md) → `image-review` | Reads a completed evaluation root, autosaves decisions, and exports corrected manifests without rewriting canonical outputs. |
| Static generated HTML review | **Active diagnostic surface** | `output_root/review/index.html` | Generated by `evaluate_dataset.py`; separate from the interactive `image-review` server and its `review_labels` state. |
| Reviewed pair/crop labels | **Active calibration fixture** | `image-label` | The checked-in examples are for regression/calibration; they are not a production corpus. |
| Saved-run comparison | **Active utility in the current source tree** | `image-compare` | Compares exact stable image-ID membership sets; it does not alter either run. |
| `scripts/review_clusters.py` | **Compatibility only** | `python scripts/review_clusters.py ...` | Thin wrapper around `image_clustering.review.cli:main`; use `image-review` for new instructions. |
| Cloud deployment or hosted review service | **Not present** | None | No container, cloud, release, authentication, or remote-service procedure is defined in this repository. |
| Unattended large production run | **Not approved by the repository docs** | None | The evaluation report explicitly recommends a staged pilot and human audit before an approximately 80,000-image run. Do not infer production readiness from a successful local test. |

## Documentation maintenance

Documentation should describe source behavior, not an assumed workflow. When behavior changes, update the narrowest canonical page and then add or repair its link here and in the root README when the change affects a common entry point.

### Source-of-truth map

| Change | Inspect and update |
| --- | --- |
| CLI name, flag, default port, or console entry point | `pyproject.toml`, the owning `src/**/cli.py`, [`DEVELOPMENT.md`](DEVELOPMENT.md), and the relevant runbook |
| Evaluation output or review input contract | `scripts/evaluate_dataset.py`, `src/image_clustering/review/dataset.py`, tests, and [`REVIEW_WORKFLOW.md`](REVIEW_WORKFLOW.md) |
| Review decision, persistence, or export semantics | `src/image_clustering/review/decisions.py`, `store.py`, `exports.py`, review tests, and [`REVIEW_WORKFLOW.md`](REVIEW_WORKFLOW.md) |
| Package boundaries or data flow | `ARCHITECTURE.md`, the root README, and the affected subsystem guide |
| Thresholds or calibration conclusions | `configs/default.json`, calibration/experiment docs, and regression tests |
| Dependency, Python, CI, or test procedure | `pyproject.toml`, `.github/workflows/tests.yml`, and [`DEVELOPMENT.md`](DEVELOPMENT.md) |

### Before finishing a documentation change

1. Verify every newly mentioned path exists from the repository root.
2. Verify CLI examples with the current parser or `--help`; use a small fixture rather than a production dataset for execution checks.
3. Run the focused tests for the changed workflow and the full test suite when practical.
4. Check relative Markdown links and search for the old command/path after renaming a workflow.
5. Mark design notes as proposals or historical material when they no longer describe the current implementation.
6. Never add credentials, tokens, private URLs, private image paths, or copied secrets. Refer to the required access mechanism without recording its value.
7. Inspect the final diff for unrelated source changes and preserve pre-existing user work.

### Reusable page template

For a new subsystem or workflow page, include:

- **Purpose and status** — what it does and whether it is active, experimental, compatibility-only, or incomplete;
- **Canonical paths and entry points** — source, script, command, config, and tests;
- **Inputs and outputs** — filenames, schemas, and ownership of generated artifacts;
- **Typical procedure** — a copyable command with prerequisites;
- **Validation** — focused tests and an observable success check;
- **Failure modes and limitations** — including unresolved uncertainty;
- **Related docs** — links back to this index and to the owning architecture/design notes.
